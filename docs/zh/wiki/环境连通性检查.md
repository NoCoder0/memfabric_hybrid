# 环境连通性检查

## 1. Device HCCS（A2/A3）

Device HCCS使用Device虚拟IP（vnic）进行通信，检查步骤如下：

### 1.1 查询Device虚拟IP（vnic）

```bash
# 查询所有device的vnic IP信息，以8卡为例
for i in {0..7}; do hccn_tool -i $i -vnic -g; done
```

### 1.2 检查Device间连通性

使用上一步查询到的vnic IP进行连通性检查：

```bash
# 检查设备a是否能ping通设备b的vnic IP
hccn_tool -i ${device_id_a} -ping -g address ${vnic_ip_b}

# 检查设备b是否能ping通设备a的vnic IP
hccn_tool -i ${device_id_b} -ping -g address ${vnic_ip_a}
```

若返回`recv time out seq`字样，说明两个设备之间不连通。

> [!TIP] 注意
> A3为一卡双die架构，两个die共用一个OS（如dev-os-0包含device 0和device 1）。同卡双die之间默认不互通（device 0和device 1不通，device 2和device 3不通，以此类推），在A3环境请注意传入的device id是否满足连通要求。如需同卡双die通信，请参考[RoCE网口网络配置](https://support.huawei.com/enterprise/zh/doc/EDOC1100494585/cabfcfaf?idPath=23710424%7C251366513%7C22892968%7C252309113%7C258915853)。

### 1.3 检查TLS配置一致性

```bash
# 检查设备的TLS状态
for i in {0..7}; do hccn_tool -i $i -tls -g; done | grep switch

# TLS使能的设备和TLS不使能的设备无法建链，建议统一保持TLS关闭
for i in {0..7}; do hccn_tool -i $i -tls -s enable 0; done
```

## 2. Device RoCE（A2/A3）

Device RoCE使用Device RDMA网卡IP进行通信，检查步骤如下：

### 2.1 查询Device RDMA网卡IP

```bash
# 查询所有device的RDMA网卡IP，以8卡为例
for i in {0..7}; do hccn_tool -i $i -ip -g; done
```

### 2.2 检查Device间连通性

使用上一步查询到的RDMA网卡IP进行连通性检查：

```bash
# 检查设备a是否能ping通设备b的RDMA IP
hccn_tool -i ${device_id_a} -ping -g address ${rdma_ip_b}

# 检查设备b是否能ping通设备a的RDMA IP
hccn_tool -i ${device_id_b} -ping -g address ${rdma_ip_a}
```

若返回`recv time out seq`字样，说明两个设备之间不连通。

> [!TIP] 注意
> A3一卡双die之间RDMA可能不通，即便`ping`成功也不代表RDMA可用，最准确的判断方式是使用打流验证，参见[传输链路打流](#传输链路打流)。

### 2.3 检查TLS配置一致性

与Device HCCS相同，参与建链的两端TLS配置必须保持一致，检查方法参见[1.3 检查TLS配置一致性](#13-检查tls配置一致性)。

## 3. Device / Host UB

### 3.1 查看本地UB EID

```bash
urma_admin show
```

如需进行打流验证，参见[传输链路打流](#传输链路打流)。

## 4. UBoE

查询Device bond IP和默认网关：

```bash
for device_id in {0..7}; do
    echo "device ${device_id}"
    hccn_tool -g -ip -i "${device_id}" -d "bond${device_id}"
    hccn_tool -g -gateway -i "${device_id}" -d "bond${device_id}"
done
```

检查链路：

```bash
# 通过-i指定源device id
# -src_address对应的是源设备的uboe device bond IP
# -dst_address指定其他设备的bond IP或者某个设备对应的网关IP
hccn_tool -t -ping -i 0 \
    -src_address 10.10.28.2 \
    -dst_address 10.10.29.2 \
    -pkt 1024
```

查询NPU网络设备状态：

```bash
# 通过-i指定源device id
hccn_tool -g -dev_info -i 0
```

## 5. Host RoCE

检查Host RoCE网卡和RDMA设备映射：

```bash
ibdev2netdev
ip addr show
```

使用RDMA工具在两端打流，验证RoCE网卡连通：

```bash
# server
ib_write_bw -d <ib_dev>

# client
ib_write_bw -d <ib_dev> <server_ip>
```

## 6. UB_RTP

检查Device侧EID和网络设备状态：

```bash
hccn_tool -g -dev_info -i <device_id>
```

查询结果中，如果出现类似`0000000000ff0a80000000000a140200`这种中间对应位置为`0a80`的，即为UB_RTP对应的EID。

如果使用手工LocalCommRes，需要确认`comm_id`填写的是当前Device实际存在的UB_RTP EID，并通过Quick Start或benchmark做最小传输验证。

device侧打流命令：

```bash
# -d 后面跟的 udmac0d0e3 替换为实际的name
# 可通过上述 hccn_tool -g -dev_info -i <device_id> 查找
# -s 为传输大小

# server
urma_perftest write_bw -y -s 67108864 -I 256 --hugepage_size 2MB \
    -d udmac0d0e3 \
    --eid_idx 0 \
    --tp_aware \
    --priority 0 \
    --enable_ipv6 \
    --bind_ip <server端device_eid>

# client
urma_perftest write_bw -y -s 67108864 -I 256 --hugepage_size 2MB \
    -d udmac0d0e3 \
    --eid_idx 0 \
    --tp_aware \
    --priority 0 \
    --enable_ipv6 \
    --bind_ip <client端device_eid> \
    -S <server端device_eid>
```

# 传输链路打流

连通性检查通过后，可通过打流工具进一步验证各协议链路的实际传输能力。

## 1. Device RoCE（A2/A3）

A3一卡双die之间RDMA可能不通，即便`ping`成功也不代表RDMA可用，最准确的判断方式是使用`roce_test ib_send_bw`打流：

```bash
# 接收端（先执行）
/usr/local/Ascend/driver/tools/hccn_tool -i 0 -roce_test reset
/usr/local/Ascend/driver/tools/hccn_tool -i 0 -roce_test ib_send_bw -s 65536 -n 1000 -tcp

# 发送端（后执行）
/usr/local/Ascend/driver/tools/hccn_tool -i 1 -roce_test reset
PEER_IP=$(/usr/local/Ascend/driver/tools/hccn_tool -i 0 -ip -g 2>/dev/null | sed -n 's/^ipaddr:\(.*\)/\1/p' | head -1)
/usr/local/Ascend/driver/tools/hccn_tool -i 1 -roce_test ib_send_bw -s 65536 -n 1000 address "$PEER_IP" -tcp
```

打流成功时会显示带宽和延迟统计结果，说明两个Device之间RDMA链路正常。

## 2. Host RoCE（A5）- CX7三方网卡

使用RDMA工具`ib_write_bw`验证两台设备RoCE网卡之间的连通性：

```bash
# server端
ib_write_bw -d mlx5_17 -x 3 -a

# client端（后面ip为server端ip）
ib_write_bw -d mlx5_0 -x 3 10.10.10.216 -a
```

* `-d mlx5_17`：指定使用的RDMA设备。
* `-x 3`：指定使用GID Index 3。
* `-a`：全自动模式，会循环测试不同大小的数据包。

## 3. UB（A5）

### 3.1 通用打流命令格式

```bash
# ========== Server 端（需先执行） ==========
# <udma_idx>: 本端实际使用的 EID 对应的 udma 索引（如 udmac0d1e6、udmac1d1e6）
# <eid_idx>:  EID 索引（如 eid1 对应 1）
urma_perftest send_lat -n 10 -s 2 -I 128 -d <udma_idx> --eid_idx <eid_idx> --tp_aware --ctp --enable_ipv6

# ========== Client 端（需后执行） ==========
# <remote_eid>: 对端 EID（需带 ":" 分隔符）
# <local_eid>:  本端 EID（需带 ":" 分隔符）
urma_perftest send_lat -n 10 -s 2 -I 128 -d <udma_idx> --eid_idx <eid_idx> --tp_aware --ctp --enable_ipv6 -S <remote_eid> --bind_ip <local_eid>
```

### 3.3 打流结果判断

#### 打流成功

显示正常的延迟统计结果，说明两个EID之间可以正常建链传输：

```text
bytes    iterations    t_min[us]    t_max[us]    t_median[us]    t_avg[us]    t_stddev[us]    99%[us]    99.9%[us]    99.99%[us]    99.999%[us]
2        10            2.56         2.66         2.57            2.57         0.01            2.66       2.66         2.66          2.66
```

#### 打流无响应

打流一直不显示结果，可以尝试ping这两个EID。若ping不通，说明两个EID之间无法建链，需要检查是否已配置路由：

```bash
ping -6 -I <local_eid> <remote_eid>
```

#### 报错：IPv6建链失败

报错内容如下，说明该机器不支持IPv6建链，需要Host侧升级内核版本：

```text
Failed to bind ip: <local_eid>
Failed to connect <remote_eid>
```

#### 报错：CR状态异常

报错内容如下，需要检查该环境配置是否正确：

