# 大页与寄存器配置

## 0. 修改启动参数并重启

1. 编辑 GRUB 配置文件：

    ```bash
    /boot/efi/EFI/openEuler/grub.cfg
    ```

2. 在对应内核启动参数最后添加：

    ```bash
    iomem=relaxed
    ```

3. 修改完成后重启机器，使配置生效。

---

## 1. 安装 BusyBox

```bash
yum install -y busybox
```

---

## 2. 修改寄存器

### 2.1 读取寄存器

die0：

```bash
busybox devmem 0x3340004c1c
```

die1：

```bash
busybox devmem 0x7340004c1c
```

默认值：

```text
0x0F00800F
```

### 2.2 写寄存器

die0：

```bash
busybox devmem 0x3340004c1c 32 0x0F00807F
```

die1：

```bash
busybox devmem 0x7340004c1c 32 0x0F00807F
```

写完后重新读取：

```bash
busybox devmem 0x3340004c1c
busybox devmem 0x7340004c1c
```

预期值：

```text
0x0F00807F
```

# 3. HugePage 配置

根据测试场景选择配置 **1G 大页** 或 **2M 大页**。

> [!TIP] 需要注意
>
> * 配置 **1G 大页时，不要求必须清空已有的 2M 大页**。
> * 配置 **2M 大页时，建议先将 1G 大页数量设置为 0**，释放 1G HugePage 占用的物理内存后，再进行 2M 大页分配。
> * 写入 `nr_hugepages` 的数值表示期望配置的 HugePage 数量，**最终实际分配数量不一定与写入值一致**，配置完成后必须重新读取确认。

---

# 4. 配置 1G 大页

## 4.1 配置方法

例如每个 NUMA Node 期望配置 `128` 个 1G 大页：

```bash
for n in 0 1 2 3; do
    echo 128 > /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages
done
```

对应期望容量：

```text
128 × 1GB = 128GB / NUMA Node
```

4 个 NUMA Node 共：

```text
128 × 4 × 1GB = 512GB
```

### 注意

配置 1G 大页时，**不需要主动清空 2M 大页**。

如果当前系统中已经存在 2M 大页，可以保留：

```text
1G HugePage + 2M HugePage 可以同时存在
```

但已有的 2M 大页会占用物理内存，因此可能影响能够成功分配的 1G 大页数量。

---

## 4.2 查看 1G 大页配置结果

```bash
for n in 0 1 2 3; do
    echo -n "node$n: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages
done
```

例如期望配置：

```text
node0: 128
node1: 128
node2: 128
node3: 128
```

但实际可能看到：

```text
node0: 128
node1: 128
node2: 98
node3: 128
```

这并不一定代表命令执行失败。

`echo 128 > nr_hugepages` 表示向内核申请：

```text
希望该 NUMA Node 最终拥有 128 个 1G HugePage
```

但内核只能根据当前物理内存状态尽可能完成分配。

例如：

```text
node2: 98
```

说明：

```text
期望：128 个
实际：98 个
```

即该 NUMA Node 当前只能成功分配 98 个 1G HugePage。

---

## 4.3 为什么 1G 大页实际数量可能小于配置数量

### 原因 1：物理内存不足

1G HugePage 每个需要占用整整 1GB 物理内存。

例如：

```text
128 个 1G HugePage = 128GB
```

如果该 NUMA Node 当前没有足够的可用物理内存，就无法完成全部分配。

---

### 原因 2：物理内存碎片化

这是运行过程中动态申请 1G HugePage 时非常常见的原因。

1G HugePage 需要找到一块足够大的连续物理内存。

即使：

```text
free memory > 128GB
```

也不代表一定能够分配：

```text
128 × 1G HugePage
```

因为剩余内存可能已经被拆成很多不连续区域。

例如：

```text
总空闲内存：150GB
```

但可能分散为：

```text
500MB
300MB
800MB
...
```

这种情况下总空闲内存虽然很多，但无法组成足够多的连续 1GB 区域，因此 1G HugePage 分配数量会少于预期。

---

### 原因 3：当前 NUMA Node 已有其他内存占用

例如：

* 普通 4K 页
* 2M HugePage
* 进程匿名内存
* page cache
* 驱动申请内存
* 其他不可迁移内存

都会占用该 NUMA Node 的物理地址空间。

因此不同 NUMA Node 即使总内存容量相同，也可能出现：

```text
node0: 128
node1: 128
node2: 98
node3: 128
```

这种不对称情况。

---

## 4.4 查看 1G 大页剩余数量

除了查看总数量：

```bash
cat /sys/devices/system/node/node0/hugepages/hugepages-1048576kB/nr_hugepages
```

还可以查看当前未使用的 1G 大页：

```bash
cat /sys/devices/system/node/node0/hugepages/hugepages-1048576kB/free_hugepages
```

批量查看：

```bash
for n in 0 1 2 3; do
    echo "===== node$n ====="
    echo -n "total 1G: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages

    echo -n "free  1G: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/free_hugepages
done
```

其中：

```text
nr_hugepages   = 当前实际配置的 HugePage 总数
free_hugepages = 当前未被使用的 HugePage 数量
```

因此：

```text
nr_hugepages = 128
free_hugepages = 100
```

表示：

```text
总共存在 128 个 1G 大页
其中 100 个当前空闲
另外 28 个正在被使用
```

# 5. 配置 2M 大页

## 5.1 先清空 1G 大页

切换到 2M 大页测试场景时，先释放 1G HugePage：

```bash
for n in 0 1 2 3; do
    echo 0 > /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages
done
```

然后检查：

```bash
for n in 0 1 2 3; do
    echo -n "node$n: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages
done
```

期望：

```text
node0: 0
node1: 0
node2: 0
node3: 0
```

### 注意

这里同样存在一种情况：

```text
echo 0 > nr_hugepages
```

之后，实际读取结果可能仍然不是 0。

例如：

```text
node0: 0
node1: 8
node2: 0
node3: 0
```

可能的原因是：

```text
部分 1G HugePage 当前仍然正在被进程使用
```

内核无法直接释放正在使用的 HugePage。

需要先停止占用这些 HugePage 的进程，再重新执行释放操作。

可以同时检查：

```bash
for n in 0 1 2 3; do
    echo "===== node$n ====="
    echo -n "total: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages

    echo -n "free : "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/free_hugepages
done
```

如果：

```text
nr_hugepages > free_hugepages
```

说明存在正在被使用的 HugePage。

---

## 5.2 配置 2M 大页

例如每个 NUMA Node 配置 `25000` 个 2M 大页：

```bash
for n in 0 1 2 3; do
    echo 25000 > /sys/devices/system/node/node${n}/hugepages/hugepages-2048kB/nr_hugepages
done
```

每个 NUMA Node 对应：

```text
25000 × 2MB
≈ 50000MB
≈ 48.8GiB
```

4 个 NUMA Node 总计约：

```text
195GiB
```

如果需要修改数量，直接修改 `25000` 即可。

---

## 5.3 查看 2M 大页配置结果

```bash
for n in 0 1 2 3; do
    echo -n "node$n: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-2048kB/nr_hugepages
done
```

例如期望：

```text
node0: 25000
node1: 25000
node2: 25000
node3: 25000
```

但也可能出现：

```text
node0: 25000
node1: 25000
node2: 23000
node3: 25000
```

这表示 node2 没有成功分配全部 25000 个 2M HugePage。

---

## 5.4 为什么 2M 大页数量也可能不符合预期

2M HugePage 同样需要连续物理内存。

但因为单页只需要 2MB，相比 1G HugePage 更容易找到连续空间，所以通常比 1G HugePage 更容易动态分配。

实际数量不足通常与以下因素有关：

* NUMA Node 可用物理内存不足
* 内存已经被其他进程占用
* 内存碎片化
* 部分物理页不可迁移
* 仍存在其他 HugePage 或系统内存占用

因此必须以：

```text
nr_hugepages
```

实际读取结果为准，而不能仅根据 `echo` 命令判断配置成功。

---

# 6. 同时查看 1G / 2M 大页状态

推荐配置完成后统一执行：

```bash
for n in 0 1 2 3; do
    echo "========== node$n =========="

    echo -n "1G total: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages

    echo -n "1G free : "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/free_hugepages

    echo -n "2M total: "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-2048kB/nr_hugepages

    echo -n "2M free : "
    cat /sys/devices/system/node/node${n}/hugepages/hugepages-2048kB/free_hugepages
done
```

示例：

```text
========== node0 ==========
1G total: 128
1G free : 128
2M total: 0
2M free : 0

========== node1 ==========
1G total: 128
1G free : 128
2M total: 0
2M free : 0

========== node2 ==========
1G total: 98
1G free : 98
2M total: 0
2M free : 0

========== node3 ==========
1G total: 128
1G free : 128
2M total: 0
2M free : 0
```

这里 node2 的 `98` 就说明：

```text
配置目标：128 个 1G HugePage
实际成功：98 个
```

后续测试时应该按照实际分配数量评估可用大页容量。

# 7. 系统级查看

查看系统整体 HugePage 状态：

```bash
grep -i huge /proc/meminfo
```

重点字段：

```text
HugePages_Total
HugePages_Free
HugePages_Rsvd
HugePages_Surp
Hugepagesize
```

但 `/proc/meminfo` 是系统整体视角。

如果测试涉及 NUMA 亲和，建议优先查看：

```text
/sys/devices/system/node/nodeX/hugepages/
```

以确认每个 NUMA Node 实际分配的大页数量。

---

# 8. 配置原则总结

## 使用 1G 大页

直接配置：

```bash
for n in 0 1 2 3; do
    echo 128 > /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages
done
```

**不要求清空已有 2M 大页。**

配置后必须重新读取 `nr_hugepages`，确认实际成功分配数量。

---

## 使用 2M 大页

首先释放 1G 大页：

```bash
for n in 0 1 2 3; do
    echo 0 > /sys/devices/system/node/node${n}/hugepages/hugepages-1048576kB/nr_hugepages
done
```

确认 1G 大页释放完成后，再配置 2M：

```bash
for n in 0 1 2 3; do
    echo 25000 > /sys/devices/system/node/node${n}/hugepages/hugepages-2048kB/nr_hugepages
done
```

无论配置 1G 还是 2M，都需要记住：

```text
echo 写入值 = 期望数量
nr_hugepages = 实际配置数量
free_hugepages = 当前空闲数量
```

**最终测试应以实际读取结果为准。**
